# 博客收藏与内容管理优化

**日期**: March 2, 2026 at 10:24 AM
**对话轮数**: 17
**来源**: [Gemini Chat](https://gemini.google.com/app/03667fe9c3536599)

---

## 对话背景与目标

用户在整理自己收藏的网站过程中，发现原本想放到网站导航页面的做法违背了导航的本质（大部分网站只是收藏，很少访问），更适合批量整理到文章中。但用户使用基于 Obsidian 的 WordPress 插件来写文章，遇到了分类管理和归档页面"污染"的问题。希望获得解决方案。

## 核心问题与需求

1. **收藏 vs 导航的矛盾**：如何处理那些"收藏但平时不访问"的网站链接？
2. **文章归档污染**：大量链接类文章如何避免影响博客的文章归档页面？
3. **编辑便利性**：如何让分类文章的编辑增加更加方便？
4. **技术实现方案**：如何使用 WordPress 的 CPT 或其他技术手段实现？

## 解决过程

对话提供了四种不同技术深度的解决方案：

1. **方案一（最推荐）- 自定义文章类型 (CPT)**：在 WordPress 中注册专门的"资源"容器，独立于普通文章，不污染归档页面。详细说明了在 functions.php 中添加代码或使用 Custom Post Type UI 插件的实现方法。

2. **方案二 - 标签/分类过滤**：利用 WP 的 pre_get_posts 钩子，在首页和归档中排除特定分类，同时可以手动创建页面通过 WP_Query 调取这些内容。

3. **方案三 - Obsidian 侧自动化**：平时在 Obsidian 中按分类建立文件夹，使用 Dataview 或 Python 脚本定期聚合，再发布到 WP。可以大幅减少 WP 端的文章数量。

4. **方案四 - 独立工具**：在 VPS 上部署 LinkStack 或 Heimdall 作为独立的导航/收藏服务，与主博客解耦。

5. **归档页面修改**：用户展示了现有的归档页面模板代码，询问如何修改以过滤特定标签。文章详细说明了通过修改 WP_Query 参数来排除特定分类的方法。

## 最终结果与结论

用户理解了"收藏（Archive）"与"创作（Content）"冲突的解决思路，明确了采用 CPT 方案作为最佳实践。可以创建独立于普通文章的"资源"类型文章，既保持编辑便利性，又不会污染博客归档。同时用户也获得了归档页面过滤特定标签的具体代码修改方案。

## 反思与延伸

这是一个非常典型的个人知识管理问题。用户的技术栈（Obsidian + WP 插件 + Cloudflare/VPS）已经具备一定的复杂性，通过 CPT 方案可以从数据库查询层面彻底解决问题。这种数据分离的思路对于其他类似场景（如产品展示、案例集等）同样适用。
