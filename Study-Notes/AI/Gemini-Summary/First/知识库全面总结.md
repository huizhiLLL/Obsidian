## 第一部分：AI与LLM技术

### 1.1 小模型时代的生存指南（7B-10B LLM模型应用与对比）

这章节的核心价值在于建立对模型参数量的正确认知。你获得了关于7B参数模型最关键的定位——**“黄金尺寸”**，这是消费级硬件与实用智能之间的最佳平衡点。

**核心知识点提炼：**

模型能力的分层认知至关重要。7B模型被比喻为“实习生”，适合执行特定任务和简单推理；而旗舰模型则相当于“教授”，拥有丰富的世界知识和复杂的推理能力。这种比喻帮助你建立了清晰的预期管理：不应该期待小模型完成复杂推理任务，但在RAG终端、代码补全、数据清洗、垂直专家模型等垂直场景下，小模型完全可以胜任。

本地部署的门槛比你想象的要低。Ollama + Chatbox的组合是最佳入门方案，DeepSeek-R1-Distill-Qwen-1.5B是推荐的起步模型。你甚至探讨了0.5B-3B的SLM（Small Language Model）在更低资源场景下的应用可能性。

**实践指导：**
- 消费级GPU（8GB+ VRAM）或Apple Silicon即可运行7B模型
- 使用`ollama run deepseek-r1:1.5b`命令快速启动
- Chatbox配置只需指定模型为`ollama/deepseek-r1:1.5b`，API地址为`http://localhost:11434`

### 1.2 AI Agent的新基建（MCP：AI Agent的新标准）

这是知识库中最具前瞻性的章节之一，涉及到了AI Agent领域的最新标准协议。MCP（Model Context Protocol）被定位为**“AI时代的USB-C接口”**，其核心价值在于统一AI与外部系统的通信标准。

**核心知识点提炼：**

MCP的三大核心能力构成了其技术基础：Resources（读取资源）、Tools（使用工具）、Prompts（获取提示）。与传统插件模式的“触发式”交互不同，MCP实现了“决策式”交互——AI可以自主决策调用哪些工具来完成任务。

Agent Skills的动态工具检索机制包含三个关键环节：技能库注册、语义检索、动态加载。这使得MCP + RAG的组合模式成为可能，实现了知识检索与工具调用的深度融合。

**实践指导：**
- SSE和Stdio两种连接方式的选择：SSE适合远程服务，Stdio适合本地工具
- MCP Server配置示例展示了标准的JSON配置格式
- 建议从最简单的“Linux MCP Server”开始练手

### 1.3 对话上下文的记忆机制（Gemini对话上下文的记忆机制）

这章节帮助你建立了对AI产品记忆机制的完整认知，并提供了高效利用AI的实践方法。

**核心知识点提炼：**

Gemini的记忆机制包括三个层面：Saved Info（跨对话的持久信息存储）、Gems（预设对话环境，类似定制化助手）、对话隔离（不同对话上下文相对独立）。理解这些机制对于高效使用AI工具至关重要。

不同AI产品的记忆机制存在差异：ChatGPT采用会话级记忆，长期记忆需要Plus订阅；Claude采用项目制隔离，适合多任务场景；Copilot则与GitHub数据打通。

**实践指导：**
- 为不同场景创建专门的Gem配置，可以显著提升对话效率
- 建议建立用户画像（如同济机械大二、魔方大神、INFJ），帮助AI更好地理解你的背景
- 使用结构化提问模板（背景、需求、约束、问题）可以获得更准确的回答

## 第二部分：后端开发

### 2.1 NestJS重构项目设计建议

这章节是后端开发的重点，涉及从MongoDB到PostgreSQL的数据库迁移，以及NestJS框架的深度应用。

**核心知识点提炼：**

重构的正确顺序应该是：数据库表单设计 → 后端架构搭建 → API接口定义 → 前端重构。数据存储格式直接决定了业务逻辑的复杂度，因此从数据库设计开始是最佳实践。

NoSQL到SQL的转换需要实行强Schema。Prisma作为ORM工具，对从NoSQL转型到SQL的开发者非常友好，学习曲线低且类型安全。数据标准化也是关键：WCA成绩应该存储毫秒而非字符串。

**核心警示：图像永远不要存Base64。** 这是一个常见的性能陷阱，Base64存储会导致数据库性能雪崩、传输开销大、无法利用CDN等问题。正确的做法是使用Presigned URL（最佳实践）或后端中转方案。

**技术栈总结：**
- 后端框架：NestJS + TypeScript
- 数据库：MySQL/PostgreSQL
- ORM：Prisma（推荐）或TypeORM
- 认证：JWT
- API文档：Swagger（自动文档生成）
- 图像存储：Cloudflare R2或MinIO

### 2.2 网站重构与工程化方案

这是对现有Web项目进行全面升级的路线图，从“脚本式”开发走向“工程级”架构。

**核心知识点提炼：**

Vibe Coding（灵感式编程）与工程化的区别需要明确：灵感爆发靠vibe coding，长久维护靠工程化。NestJS + PostgreSQL + Vue3 + Tailwind是经过验证的成熟技术组合。

JSONB类型是PostgreSQL相比MongoDB的重大优势，可以在保持关系型数据优势的同时处理灵活字段。Redis Pub/Sub可以实现与AstrBot等服务的解耦通信。NestJS内置的Cron模块提供了定时任务能力。

**内存需求评估：**
- NestJS：150-350MB
- PostgreSQL：80-256MB
- Nginx：10-30MB
- 1Panel：150-300MB
- 极限情况1GB即可运行，2GB为舒适区间

## 第三部分：嵌入式与硬件

### 3.1 ESP32嵌入式AIoT全栈学习路线

这是嵌入式开发的系统化学习路径，覆盖了从入门到进阶的完整阶段。

**核心知识点提炼：**

**放弃Arduino IDE，使用PlatformIO。** 这是最重要的建议——PlatformIO提供更专业的项目管理、依赖管理和跨平台支持。

嵌入式开发需要建立“实时循环”思维：不同于Web开发的事件驱动模型，嵌入式开发是while True的实时循环，物理世界没有Ctrl+Z。限位保护是嵌入式开发的第一要务。

**学习阶段划分：**

- 第一阶段（2-3天）：点灯与GPIO
- 第二阶段（3-5天）：总线协议与传感器（I2C、SPI、UART）
- 第三阶段（5-7天）：联网与全栈联动，重点是MQTT协议
- 第四阶段：机电控制（舵机、步进电机、PID控制）

**通信协议对比：** MQTT适合设备间通信（发布/订阅模式），WebSocket适合Web端实时交互。

### 3.2 智能魔方操作映射软件开发

这是将硬件、软件和个人爱好完美结合的典型项目，也是你技能树的综合展现。

**核心知识点提炼：**

技术栈选型决定了项目的成败。后端核心使用Python（bleak处理蓝牙，asyncio核心循环，pydirectinput模拟输入）；前端UI使用Vue 3 + Vite；通信桥梁推荐NiceGUI或Tauri v2；打包工具推荐Nuitka（比PyInstaller性能更好）。

原项目存在三个需要解决的核心问题：Matplotlib性能差（用Vue + Three.js替代）、硬编码（建立KeyMapper类读取JSON/YAML配置）、GAN协议耦合（剥离为独立的CubeDriver类）。

**核心经验：**
- 消除硬编码，用配置文件管理按键映射，支持多预设切换
- 保护源代码，Nuitka打包比PyInstaller性能更好
- MVP开发：先实现核心映射功能，再添加UI和高级功能

## 第四部分：运维与部署

这是Windows环境下搭建Linux开发环境的完整指南。

**核心知识点提炼：**

**部署服务示例：**

**核心知识点提炼：**

**核心经验：**

### 4.3 安卓手机部署Linux环境方案

这是移动端运行Linux的完整方案，适合学习和便携场景。

**核心知识点提炼：**

Termux是安卓终端模拟器，无需Root即可使用。PRoot-Distro是Termux官方插件，可以运行完整Linux发行版。AidLux是国产方案，提供Web桌面环境，对AI框架有优化。

**核心知识点提炼：**

## 第六部分：内容管理与效率工具

### 6.1 博客收藏与内容管理优化

这是WordPress与Obsidian集成的系统方案，解决收藏与导航的分类问题。

**核心知识点提炼：**

收藏与导航有本质区别：收藏但平时不访问的链接适合整理到文章，导航页面只放常用网站。

CPT（自定义文章类型）是最佳方案：独立于普通文章，不污染归档页面。WP_Query是WordPress自定义查询接口，pre_get_posts钩子可以在主查询执行前修改查询参数。

**四种方案对比：**
- CPT：最彻底，数据分离，但需要代码
- 标签过滤：简单易行，但可能影响其他查询
- Obsidian聚合：减少WP文章数量，但需要维护脚本
- 独立工具（LinkStack/Heimdall）：完全解耦，但需要额外部署

### 6.2 樱花粉主题的极客贯彻指南

**从小处着手：** 先从使用频率高的工具开始（VS Code、Obsidian），再逐步扩展到其他工具。

### 6.3 宿舍物品整理的计算机化方案

### 十大最佳实践

1. **7B是“黄金尺寸”**：在消费级硬件与实用智能之间取得最佳平衡，小模型适合特定任务而非复杂推理。

4. **图像永远不要存Base64**：使用URL + OSS方案，避免性能灾难。

5. **从数据库设计开始**：数据存储格式决定业务逻辑复杂度，重构应从底层开始。

6. **Vibe Coding vs 工程化**：灵感爆发靠vibe coding，长久维护靠工程化，两者需要平衡。

7. **层级式收纳**：按使用频率而非物品属性分类，这是最关键的思维转变。

8. **终端美化提升效率**：Zsh + Powerlevel10k提供更好的开发体验。

9. **提问协议提升效率**：结构化提问（背景、需求、约束、问题）可以获得更准确的回答。

10. **物理世界与数字世界的连接**：将计算机思维应用于现实，是很好的思维练习。
