### 日常任务优化

看到过一个视频，大意是一个人即便很聪明，在迫于生存压力下也会疏于优化自己的工具与工作流，从而降低自己的效率。

近期感觉的确，因为自己大概从五六月后吧，在个人日常 agent 协作开发上的摸索和优化就少了很多

然后现在搞服务器维护与迁移时，由于更偏向 agent 的操作，不得不思考如何提高这一过程的效率了，从而去优化自己的工作流

之前只是在本地维护了一个 md 文件，codex 开新聊天然后把路径给他然后说需求，慢了点，因为每次 agent 都要了解下背景去连接

现在是会单独维护一个仓库，来存放相关的凭据等信息吧，要不是现在的 codex 一直没法在我的 Windows 上 computer use，我会放更多相关的个人信息，在填更种表单时可能会遇到的，以及各种账号登录时可能会遇到的，都可以记录和供 agent 使用；还有是一些云平台的 cli 环境也配置好一同说明

然后再单独开个 skills，简单说下索引和触发场景，这样日常使用很流畅，在项目中触发也很简单

比如说“服务器上有个 xxx，帮我搞一下”，“看下服务器日志，xxx 有点问题，修一下”，“帮我直接部署到 cf 上”

关于 cf，用 wrangler 其实就足够，codex 官方是有插件，但是感觉好像有些臃肿，之前安装过？但也没仔细探究了，agent 自己的知识库与联网检索能力其实很强，过于详细的 skill 指导似乎必要性不大，对于这种有官方文档的东西

其实最近参与 cuberoot.me 的开发时，还是有学到不少东西的，对于前端 uiux 的理解更多了些，以及一些工作流关键点的吸收，这些都比较潜移默化的

不论是刷推，还是其他平台，也都会看到很多新出的，比较火的一些 agent 工具，或是什么 ui 工具，都没怎么抽出时间去试，现在比较感兴趣的还是偏向于 ui 设计的一些工具，可以一试
