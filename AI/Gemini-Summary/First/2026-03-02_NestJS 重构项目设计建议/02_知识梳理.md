# NestJS 重构项目设计建议 - 知识梳理

## 涉及的技术栈/工具

- **后端框架**：NestJS
- **数据库**：MySQL（从MongoDB迁移）
- **ORM**：Prisma（推荐）、TypeORM
- **认证**：JWT
- **API文档**：Swagger
- **图像存储**：Cloudflare R2、MinIO（OSS选型）
- **前端**：Vue3

## 关键概念与方法

- **重构顺序**：数据库表单设计 -> 后端架构搭建 -> API接口定义 -> 前端重构
- **NoSQL到SQL转换**：从MongoDB迁移到MySQL必须实行强Schema
- **数据标准化**：WCA成绩存储毫秒而非字符串
- **Base64存储危害**：
  - 数据库性能雪崩
  - 传输开销大
  - 无法利用CDN
- **图像存储方案**：
  - Presigned URL（最佳实践）
  - 后端中转方案

## 重要的代码片段或命令

```bash
# 安装Prisma
npm install prisma --save-dev
npx prisma init

# 生成Prisma Client
npx prisma generate
```

```prisma
// schema.prisma 示例
model User {
  id        Int      @id @default(autoincrement())
  username  String   @unique
  email     String   @unique
  avatar    String?  // 存储URL而非Base64
  records   Record[]
  createdAt DateTime @default(now())
}

model Record {
  id        Int      @id @default(autoincrement())
  userId    Int
  user      User     @relation(fields: [userId], references: [id])
  time      Int      // 毫秒存储
  scramble  String
  createdAt DateTime @default(now())
}
```

```typescript
// NestJS模块结构
// user.module.ts
@Module({
  imports: [PrismaModule],
  controllers: [UserController],
  providers: [UserService],
})
export class UserModule {}
```

## 可复用的经验/最佳实践

1. **从数据库设计开始**：数据存储格式决定业务逻辑复杂度
2. **Prisma对NoSQL转SQL者友好**：学习曲线低，类型安全
3. **图像永远不要存Base64**：使用URL + OSS方案
4. **JWT鉴权**：标准化的用户认证方案
5. **Swagger自动文档**：接口文档自动化生成
6. **前后端并行开发**：确定数据库和API后即可分工
