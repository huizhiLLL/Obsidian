# PaddleOCR 多进程代码分析与修复 - 知识梳理

## 涉及的技术栈/工具

- **OCR引擎**：PaddleOCRVL（基于VLM的OCR方案）
- **并发处理**：Python multiprocessing
- **运行环境**：云计算平台（GPU实例）
- **输出格式**：Markdown

## 关键概念与方法

- **多进程架构**：使用Python multiprocessing模块实现并行处理
- **路径处理陷阱**：save_to_markdown参数必须是完整文件路径，不是文件夹
- **PDF多页覆盖问题**：循环中没有区分不同页面的输出文件名
- **显存优化**：PaddleOCRVL配合多worker可能导致CUDA OOM
- **断点续传设计**：检测已完成任务并跳过

```python
# 修正后的process_one_image函数
def process_one_image(image_path: str, output_dir: str, model):
    # 正确的路径处理
    base_name = os.path.splitext(os.path.basename(image_path))[0]
    # 为PDF添加页码后缀
    pdf_page = ""
    if image_path.lower().endswith('.pdf'):
        # 从文件名中提取页码或使用索引
        pdf_page = f"_page{current_page}"
    
    # 正确的完整文件路径
    output_path = os.path.join(output_dir, f"{base_name}{pdf_page}.md")
    
    # 加载并识别
    result = model.ocr(image_path)
    
    # 保存到正确的文件
    save_to_markdown(result, output_path)
    
    return output_path
```

```python
# 多进程主函数
from multiprocessing import Pool, cpu_count

def main():
    image_files = get_image_files(input_dir)
    
    # 根据GPU显存调整worker数量
    worker_count = 2 if has_sufficient_vram() else 1
    
    with Pool(worker_count) as pool:
        results = pool.starmap(
            process_one_image,
            [(f, output_dir, model) for f in image_files]
        )
```

## 可复用的经验/最佳实践

1. **路径参数要完整**：save_to_markdown必须传入完整文件路径
2. **PDF多页区分**：为每页输出添加页码后缀避免覆盖
3. **显存监控**：遇到OOM时将worker_count改为1
4. **断点续传设计**：检测已完成任务并跳过，提高可靠性
5. **VLM OCR特殊性**：与传统OCR行为不同，需要特殊处理
